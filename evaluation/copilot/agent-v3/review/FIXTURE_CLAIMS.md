# Fixture claims, in plain English

Generated by `build_review_package.py` from the server's claim catalog. These sentences are
**everything** the system can say about each test run: it can only show claims from this
list, word for word. A label is right when it matches what these sentences support.

## Tools

The system reaches claims only through these five read-only tools.

| Tool | What it describes | Claims it owns |
|---|---|---|
| `get_run_status` | Whether this run's output is synthetic, verified real, or unverified, and its status, pipeline profile, and data origin. | `output_nature`; `run_status` |
| `get_tracking_diagnostics` | Descriptive tracking diagnostics: detection and tracklet counts, tracklet durations, assignment, active tracklets, and what the diagnostics do not establish. | `diag_active`; `diag_assignment`; `diag_duration`; `diag_ground_truth`; `diag_insufficient`; `diag_interpretation`; `diag_legacy_tracking`; `diag_reliability_scope`; `diag_short_tracklets`; `diag_synthetic`; `diag_tracking` |
| `get_artifact_metadata` | How many artifacts this run registered, and how many passed integrity verification. | `artifact_integrity` |
| `get_model_provenance` | Recorded model references, code revision, source-video checksum, and source duration. | `model_details`; `model_references`; `provenance`; `source_duration` |
| `get_evidence_limitations` | What evidence is missing for this run, and what is never measured or claimed. | `boundaries`; `missing_evidence`; `no_missing_evidence` |
